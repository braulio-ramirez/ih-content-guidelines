# Buttons (CTAs)

Buttons start a process, submit a form, change a view, or delete something. Other names: call-to-action (CTA), action.

## Hierarchy (when it changes words)

- **Primary:** most important action in a series, or the action that completes a task (e.g. “Finish”). Avoid more than one primary action in a single section.
- **Secondary:** default.
- **Tertiary:** low importance; dismissive actions that cancel, dismiss, or skip (e.g. “Maybe later” under “Get started”). Closing a window uses an **X**, not the word “close.”
- **Destructive:** irreversible data loss (e.g. deleting an allergy). Treat as high-stakes; keep the label clear.

Avoid disabled buttons unless necessary. Prefer letting the member hit an error with an explanation. If a button must be disabled, put the reason next to it (e.g. disabled “Join visit” with “You can join the visit 20 minutes before your appointment start time.”).

## Word choice

- Aim for 1–2 words, **3 words max** (content spec also allows **4 max**). Never truncate with ellipses.
- If the action needs more words, explain before or after the button; keep the label short.
- Avoid superfluous words like “now” unless needed for context (“See a doctor now” for Urgent Care — not “Get started now”).
- Prefer short words: `book` instead of `schedule`, `visit` instead of `appointment`, unless a parent component locks a different CTA.
- Match language in nearby headers and body copy.
- Use verbs that make the action clear.
- Labels must be unique on the same screen — no two identical button labels.

## Grammar

- Sentence case, not Title Case or ALL CAPS (“Book visit” not “Book Visit” or “BOOK VISIT”).
- Omit punctuation (periods, commas, exclamation marks).

## Assistive technology

- Default accessible name = visible label.
- If the visible text is not descriptive enough, or several buttons share the same text, provide a more specific accessible label (e.g. visible “Remove” → “Remove Zoloft”).
- In the loading state, the accessible label should be **loading**.
